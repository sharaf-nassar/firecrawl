# Plan: mcp-capability-gaps

## Architecture Approach

Four coordinated moves, per the spec's Clarifications (all seven decided; codex-shim backend, both-layer fail-fast with probed-alive semantics, interact rewrite+intercept with drift guard, disabled-by-default fresh state, json-format scrape in scope, sibling audit out of scope).

**1. Host-side codex-shim service — `apps/codex-shim/`.** A small dependency-free Node service (plain `.mjs`, `node:http`, `node:test` — mirroring `apps/browser-interaction-worker`'s pattern, `apps/browser-interaction-worker/package.json:8`) exposing:

- `POST /v1/chat/completions` — translates each OpenAI-style request into `codex exec --ephemeral --json -m <model> -c model_reasoning_effort=<effort>`, writing `--output-schema <tmpfile>` when the request carries `response_format: { type: "json_schema" }`. Messages are flattened into the exec prompt (system + user turns concatenated with role markers); the JSON event stream from `--json` is parsed for the final agent message, which is returned as a chat-completion response body (single choice, `finish_reason: "stop"`, synthesized `usage` from the event stream when available).
- `GET /v1/models` — cheap OpenAI-compatible listing (`gpt-5.6-luna`, `gpt-5.6-terra`); doubles as the API-side probe target (uniform across shim/hosted/Ollama, unlike a bespoke health route).
- `GET /health` — 200 JSON `{ status, backend: "codex-shim", models: { small, main }, concurrency }` when the `codex` entrypoint resolves and `~/.codex/auth.json` exists/has sane mode (same checks `scripts/local-firecrawl` already codifies in `resolve_local_codex_runtime`, `scripts/local-firecrawl:92-195`); 503 otherwise. Never echoes auth material (spec Clarifications Q7).
- `POST /v1/embeddings` → 501 (spec Constraints: both extract rerankers use `generateCompletions`; `getEmbeddingModel` feeds only `lib/ranker.ts`, unused outside tests).
- Model/effort mapping keyed by **incoming model name** (resolves spec Open Question 3): names matching `mini|nano` (the `gpt-4o-mini`-class gating call sites) → `gpt-5.6-luna` / `model_reasoning_effort=low`; everything else (`gpt-4.1`-class main extraction) → `gpt-5.6-terra` / `medium`. Rules live in shim config (env-overridable), not `MODEL_NAME` (which would flatten both tiers, `apps/api/src/lib/generic-ai.ts:60`).
- Concurrency cap: at most `CODEX_SHIM_MAX_CONCURRENCY` (default 2) concurrent `codex exec` children; excess requests queue FIFO (mitigates parallel extract-chunk fan-out, see Risks).

Why `apps/` not `scripts/`: it is a long-lived service with its own test suite and translation logic, not orchestration glue; `apps/` is where services live (`apps/browser-interaction-worker`, `apps/browser-service`), `scripts/` holds lifecycle wrappers. Rejected alternatives (spec Clarifications Q1): in-container codex provider (needs host `~/.codex` + host `codex` binary — impossible under compose without violating the no-secret-in-compose posture), Codex `app-server`/`exec-server` (experimental, explicitly not used), Ollama (spec Non-Goals: no local model hosting).

**Shim port/bind (resolves Open Question 1):** default `CODEX_SHIM_PORT=3030`, bind `0.0.0.0` — the `api` container reaches it as `http://host.docker.internal:3030/v1` via the existing `extra_hosts: host.docker.internal:host-gateway` (`docker-compose.yaml:15-16`) and env passthrough (`docker-compose.yaml:37-41`); a `127.0.0.1` bind would be unreachable from the bridge. Unauthenticated exposure = subscription-quota burn, the accepted risk of Clarifications Q7; docs note operators may firewall the port.

**Shim supervision (resolves Open Question 2): managed by `scripts/local-firecrawl` as a host process** with pidfile + logfile — new `shim-start` / `shim-stop` subcommands plus a shim line in `status`. Rationale: compose cannot host it (needs host `~/.codex`); systemd would fork the operator story across init systems and duplicate the codex/auth validation `local-firecrawl` already owns (`resolve_local_codex_runtime`, `scripts/local-firecrawl:92-195` — reused verbatim for shim preflight). Pidfile in the existing 0700 control dir (`$XDG_RUNTIME_DIR/firecrawl-control/codex-shim.pid`, dir handling at `scripts/local-firecrawl:31-33,214-223`); logs to `${XDG_STATE_HOME:-$HOME/.local/state}/firecrawl/codex-shim.log` (runtime dir is tmpfs), size-capped/rotated so append-only growth is bounded. Lifecycle integration: `local-firecrawl stop` and `restart` (`scripts/local-firecrawl:1478,1486`) also stop/restart a running shim — no orphaned unauthenticated listener may remain on :3030 after teardown; `local-firecrawl logs` gains a `shim` target routed through the existing `redact_local_logs` machinery (`scripts/local-firecrawl:1289,1320,1550`). Crash recovery is decided explicitly: **no auto-restart** — a crashed shim stays down and is surfaced by both fail-fast layers (hidden MCP tool + API 400), not resurrected by a supervisor. `local-firecrawl start` does **not** auto-start the shim — fresh setup stays explicitly disabled (Clarifications Q2); enablement is the two documented steps (start shim, set `OPENAI_BASE_URL`). (Asymmetry is deliberate: `stop` tears the shim down for safety; `start` never brings it up unbidden.)

**2. API-side fail-fast (Story 2 backstop).** (a) Empty-string→undefined coercion applied per-field to exactly the five LLM vars in `apps/api/src/config.ts` (`OPENAI_API_KEY`/`OPENAI_BASE_URL` at :70-71; `MODEL_NAME`/`MODEL_EMBEDDING_NAME`/`OLLAMA_BASE_URL` at :313-315) — scoped coercion, no central transform (Clarifications Q3); `generic-ai.ts` stays untouched (Clarifications Q5) but no longer constructs `createOpenAI({ apiKey: "" })` from `init-local-env.sh`'s scaffolded empties (`scripts/init-local-env.sh:83-88`). (b) A precondition helper (new `apps/api/src/lib/extract/llm-precondition.ts`) evaluated at the top of `extractController` (`apps/api/src/controllers/v2/extract.ts:25-38`, before `saveExtract`/enqueue at :98-113): if no backend is configured (post-coercion: no `OLLAMA_BASE_URL`, no `OPENAI_BASE_URL`, no `OPENAI_API_KEY`) → immediate 400 naming the missing backend and the enablement steps; if configured → probed alive → 400 naming the unreachable endpoint on failure. **Probe semantics:** OpenAI-style configs get `GET <OPENAI_BASE_URL>/models` carrying `Authorization: Bearer <OPENAI_API_KEY>` (placeholder or real key); **any HTTP response counts as alive** — including 401/403/404 — so hosted OpenAI with a real key and the auth-ignoring shim both pass; only a network error or timeout counts as dead. Ollama-style configs (`OLLAMA_BASE_URL` set — the `defaultProvider` branch, `apps/api/src/lib/generic-ai.ts:22,29-31`) probe `GET <base>/api/tags` instead (normalizing a trailing `/api` on the configured base so the path is not doubled), because the native Ollama root 404s `GET /models`. Timeout policy: 1.5s per probe, result cached ~15s, **fail-closed** — a probe timeout disables extract (400) rather than enqueueing a job that dies in the worker; the fail-closed choice is documented so operators on slow links check the probe first. This replaces today's 200-then-`failed` path where the worker's first LLM call 401s (`apps/api/src/services/extract-worker.ts:86-135`).

## Data Model

None beyond shim config. The shim is stateless per-request (tmpfiles for `--output-schema` are created and deleted per call); its configuration is env vars (`CODEX_SHIM_PORT`, `CODEX_SHIM_HOST`, `CODEX_SHIM_MAX_CONCURRENCY`, model-tier overrides) with in-code defaults. No DB, queue, Redis, or MinIO schema changes; `extract.jobs`/`extract.dlx`/`extract.dlq` semantics untouched (spec Non-Goals).

## API / Interface Changes

- **New shim HTTP surface** (host, default `0.0.0.0:3030`): `POST /v1/chat/completions` (OpenAI-compatible subset: `model`, `messages`, `response_format: json_schema`, `temperature` ignored), `GET /v1/models`, `GET /health`, `POST /v1/embeddings` → 501. Auth header accepted and ignored.
- **`POST /v2/extract` behavior change**: returns 400 (was 200 + id) when the LLM backend is unconfigured or fails the liveness probe. Breaking for non-MCP consumers (JS SDK, curl) that previously got 200-then-`failed` — this is the intended Story 2 backstop; existing operators with today's empty-string `.env` move from silent-fail to an actionable 400 (flagged in spec review "no upgrade path" note; called out in docs). Requests with a live backend are unaffected; error body follows the existing `{ success: false, error }` shape (`apps/api/src/controllers/v2/extract.ts:33-37`).
- **Accepted asymmetry — json-format scrape has no precondition gate.** The fail-fast gate lands only in `extractController`. `POST /v2/scrape` with `formats: ["json"]` against a dead/unconfigured backend still fails late: the scrape itself succeeds and the provider error (connection refused / AI SDK `APICallError` text) surfaces inside the json format result/warning of the returned document rather than as a pre-enqueue 400. This is recorded as an accepted decision — extending the gate to the scrape controller is explicit follow-up work, not in this epic's scope.
- **MCP `tools/list` changes**: `firecrawl_extract` present only when the shim health probe succeeds at session start; `firecrawl_interact` entry rewritten (prompt-only description, no `code` in `inputSchema`, `language` const `"node"`). `firecrawl_interact_stop` and the existing 7 disabled tools unchanged.
- **MCP `tools/call` changes**: `firecrawl_extract` when hidden → existing `-32601` disabled-tool error; `firecrawl_interact` with `code`/non-node `language` → invalid-params error stating the local runtime is prompt-driven only.
- **`local-firecrawl` CLI**: new `shim-start`/`shim-stop` subcommands; `status` output gains one line, e.g. `Extract: enabled via codex-shim (http://127.0.0.1:3030, models gpt-5.6-luna/gpt-5.6-terra)` or `Extract: disabled (OPENAI_BASE_URL unset / shim unreachable)` — never echoing `~/.codex` material (Clarifications Q7).
- **`browserExecuteRequestSchema` unchanged** (`scrape-browser.ts:109-117`): `language: z.literal("node")` kept (Open Question 6 → keep-as-is; the JS SDK always sends `"node"`, `apps/js-sdk/firecrawl/src/v2/methods/scrape.ts:50-70`).

## Testing Strategy

**De-risking spike (first, manual — spec Open Question 4 / review recommendation):** one full extract through the shim before the e2e test item is sized. The spike gates **only** the e2e test item (its sizing depends on the spike's latency and fixture-reachability findings); the orchestration, API fail-fast, and launcher-gating items may proceed in parallel with it. Procedure: hand-start the shim, hand-set `OPENAI_BASE_URL`/`OPENAI_API_KEY` in `.env`, `local-firecrawl restart`, `POST /v2/extract` + poll. Nothing past the first LLM call has ever run self-hosted (fire-0 DB/Redis/MinIO interactions); this run also verifies the fixture reachability assumption below and produces a real latency number for the timeout risk.

**Unit — shim (`apps/codex-shim/src/*.test.mjs`, node:test):** request translation (messages → exec prompt; `-m`/`-c model_reasoning_effort` argv assembly; `response_format: json_schema` → `--output-schema` tmpfile written with the exact schema and cleaned up), model mapping (`gpt-4o-mini`→luna/low, `gpt-4.1`→terra/medium, unknown→terra/medium), `/v1/models` and `/health` shapes, 501 embeddings, concurrency cap queueing, malformed-codex-output error mapping. `codex` is stubbed with a fake executable (same technique as `scripts/local-firecrawl.test.mjs`'s PATH-stubbing harness).

**Unit — launcher (`scripts/local-firecrawl-mcp.test.mjs`, node:test — extends the `scripts/` node:test pattern established by `scripts/local-firecrawl.test.mjs`; the launcher itself currently has no tests):** tool-list filtering incl. dynamic extract hiding; interact entry rewrite (no `code` key, no bash/python mention, no stdout/stderr claims in description); code-call intercept (code present, language bash/python) vs pass-through (prompt-only, language node); probe behavior (health up/down/timeout, `.env` parsing, host.docker.internal translation); **drift-guard snapshot**: rewritten entry deep-equals checked-in expectation and the fixture's recorded upstream version equals the version pinned in the launcher source (`firecrawl-mcp@3.22.3`), failing loudly on a bump.

**Unit — API (vitest, `apps/api`):** config coercion (five vars: `""` parses to `undefined`; other optional vars unaffected) and `llm-precondition` logic (unconfigured → reason; configured+probe-fail → reason; TTL cache) as isolated vitest units alongside the existing suite (`apps/api/package.json:24`).

**Integration/e2e (vitest snips, new `apps/api/src/__tests__/snips/v2/extract-local.test.ts`, run like `test:snips:local-browser` against the live stack, `apps/api/package.json:30`):**

## Risks

- **Spawn latency vs MCP client timeout.** ~2-10s per `codex exec` across gating + per-URL + rerank calls, while upstream `firecrawl_extract` blocks polling until completion (spec Open Question 5). Mitigations: luna/low for gating calls, tiny e2e fixture, shim concurrency cap; spike produces a real number. Residual: large multi-URL extracts may exceed client budgets — document raw-API polling as the fallback; do not attempt streaming in this epic.
- **`codex exec` output variance vs strict `json_schema`.** `--output-schema` constrains the final message, but transcript noise/partial JSON is possible. Mitigation: shim parses the `--json` event stream for the final structured message only, validates it is parseable JSON before responding, and maps failures to an OpenAI-style error (surfaces as a failed extract, not a hang). Fixture schema kept trivially satisfiable.
- **Upstream `firecrawl-mcp` bump re-advertising code execution or extract.** Drift guard (version-pin assertion + rewrite snapshot) fails the launcher test suite on any bump, forcing a deliberate re-review (Clarifications Q4).
- **Host-process supervision fragility.** Pidfile staleness, port squatting, log growth. Mitigations: `shim-start` verifies liveness before/after spawn and refuses on a live pid; `shim-stop` validates pid ownership; both layers of fail-fast make a dead shim visible (hidden tool + 400) rather than silent; logfile lives in XDG state (not tmpfs) and is size-capped/rotated. These three failure modes are acceptance criteria on the shim orchestration sequencing item, not just aspirational mitigations.
- **Concurrent `codex exec` spawns from parallel extract chunks.** Fire-0 fans out per-URL; uncapped spawns could thrash CPU/quota. Mitigation: shim-side concurrency cap (default 2) + FIFO queue; queue depth exposed on `/health` for observability.
- **`~/.codex` auth token refresh under concurrent use.** Concurrent `codex exec` processes may race on token refresh in `auth.json`. The browser-interaction-worker already serializes refresh with an `AbortableMutex` (`apps/browser-interaction-worker/src/codex-runner.mjs:838-1075`); the shim's concurrency cap reduces exposure, and if the spike shows corruption, adopt the same mutex-around-spawn pattern shim-side (noted in the shim core item's acceptance).
- **Fixture reachability assumption.** `host.docker.internal` scraping from the fetch/playwright engines is unverified (playwright-service may lack `extra_hosts`). Spike verifies; fallback is serving the fixture from an existing in-network container port.
